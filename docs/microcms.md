# microCMS設計

4 APIを使用する案です。カテゴリ・地域は別APIに分割しません。
以下のフィールドIDは実装と合わせるための設計値で、CMSへの登録は未実施です。

## reports（リスト形式）

| ID | 種別 | 用途 |
| --- | --- | --- |
| title | テキスト | 記事タイトル |
| publishedAt | 日付 | microCMS標準の公開日時を利用 |
| location | テキスト | 取材地 |
| media | テキスト | 掲載媒体 |
| category | セレクト | 現地ルポ / 調査報道 / 寄稿・コラム / 映像 |
| lead | テキストエリア | リード文 |
| eyecatch | 画像 | 記事写真 |
| body | リッチエディタ | 本文HTML |

`publishedAt` はカスタムフィールドとして重複作成しません。掲載日をCMSの公開日と分ける必要がある場合は、別フィールドを設計します。
カテゴリは単一選択を想定します。API応答が配列である点を取得処理に反映します。
標準のコンテンツIDを詳細ページのURLに使用し、公開後の変更は避けます。

## 実装前に確定するルール

- 各フィールドの必須・任意、未入力時の表示。
- 記事の並び順、写真の並び順、同順位の場合の順序。
- 写真の代替テキスト。説明用フィールドの追加が必要か検討。
- 本文の見出し、引用、リンク、画像、動画埋め込みの許可範囲。
- HTMLのサニタイズ方針、外部URLの許可スキーム。任意HTMLを無条件で表示しない。

連絡先フィールドには公開してよい情報だけを入力します。秘密鍵や認証情報は登録しません。
写真のキャプションを事実に合わせ、サンプル写真を実際の取材実績として扱わない方針です。
