# 運用・公開準備

外部サービスの作成やデプロイは未実施です。本書は実装時の設定方針です。

## 環境と納品方針

開発・動作確認は制作者自身の環境で行います。納品時にクライアントがCloudflareアカウントを作成し、そのアカウント内のCloudflare Pagesへ本番サイトをデプロイします。
開発用Pagesプロジェクトのアカウント移管を前提にせず、本番側でプロジェクト・環境変数・Deploy Hookを設定し直す方針です。
詳細は[納品・本番公開手順](handover.md)に記録します。GitHub・microCMS・ドメインの所有者と保守範囲は、納品前に別途確定します。

## Cloudflare Pages

| 項目 | 予定値 |
| --- | --- |
| 生成方式 | Astro SSG |
| ビルドコマンド | `npm run build`（npm採用時） |
| 出力先 | `dist` |
| ビルド元 | GitHubの本番用ブランチ。名称は設定時に確認 |

パッケージマネージャーとNode.jsのバージョンを決め、ローカル・CI・Pagesでそろえます。
静的サイトとして配信し、SSRやPages Functionsは初期構成に含めません。

## ビルド時の環境変数

| 名前 | 用途 | 扱い |
| --- | --- | --- |
| MICROCMS_SERVICE_DOMAIN | microCMSのサービス識別子 | ビルド時のみ |
| MICROCMS_API_KEY | Content APIの読み取りキー | シークレットとして管理 |
| SITE_URL | 公開サイトの絶対URL | canonical・OGPなどに使用 |

実装時に値を含まない `.env.example` を追加します。キーに `PUBLIC_` を付けず、成果物・ログ・Gitに含めません。
プレビュー環境と本番環境の変数は、それぞれ設定・確認します。

## Webhook

Pagesで対象ブランチのDeploy Hookを作成し、microCMSのWebhook送信先に設定します。
Hook URLはビルドを起動できる情報として秘密に扱います。

- 公開、新しい公開内容への更新で再ビルドします。
- 公開停止・削除でも再ビルドし、古い記事が配信され続けることを防ぎます。
- 下書き保存ではビルドしない方針です。各イベントの実際の発火条件は接続時に確認します。
- 公開中の4 APIすべてを対象にします。短時間の連続更新ではビルド回数に注意します。

Webhookの送信成功だけで公開完了とはみなしません。Pagesのビルド成功と公開URLへの反映を確認します。
失敗時はキー・API権限・スキーマ・ビルドログを確認し、修正後に再ビルドします。
緊急の公開停止では再ビルド完了と記事URLの応答も確認します。

## 無料枠と画像

無料枠での運用を目標にしますが、費用が発生しないことを保証する設計ではありません。
依頼案の数値は以下のとおりです。最新プランの確認前のため、契約・公開前に公式情報と照合します。

| サービス | 依頼案の上限・仕様（未検証） |
| --- | --- |
| microCMS Hobby | 5 API、10,000件、転送20GB/月、ストレージ無制限 |
| Cloudflare Pages Free | 500ビルド/月、帯域幅無制限、1ファイル25MiB |

SSGで閲覧時のContent API通信をなくします。ただし画像をmicroCMSから直接表示する場合、その画像配信の転送量は発生します。
画像URLの幅指定・WebP変換などで容量を抑え、表示サイズ、縦横比、遅延読み込みを設定します。
動画は外部埋め込みを想定し、掲載許可と読者のプライバシーへの影響を確認します。

## 公開前の確認

- API全件取得、空データ、API障害でのビルド動作。
- 公開・更新・公開停止・削除とWebhookの連動。
- 全ページのリンク、404、canonical、OGP、モバイル表示。
- キーボード操作、代替テキスト、文字のコントラスト。
- APIキーが生成HTML・JavaScript・ログに含まれないこと。
- 原稿・写真・媒体ロゴの利用許可、連絡先の公開範囲。
- 独自ドメイン・HTTPSと、失敗時の復旧手順。
